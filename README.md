# Software-Quality-Testing-and-Practice
以网上书店项目中的代码模块作为被测对象，展开相关测试实践。

## 目录结构

```text
3测试代码及产品源代码/
└── be/
    ├── src/
    │   ├── config/         # 数据库、接口及认证配置
    │   ├── middleware/     # 身份认证与权限校验
    │   ├── routes/         # 用户、供应商、图书、购物车、订单接口
    │   ├── services/       # 图书与订单服务
    │   └── utils/          # 公共工具
    └── cypress/
        ├── e2e/
        │   └── api/        # 接口测试代码（*.cy.ts）
        ├── fixtures/       # 测试数据
        ├── plugins/        # 数据库任务等测试插件
        └── support/        # 公共测试命令与初始化
```

## 分批上传说明

- A 负责用户与供应商模块，B 负责图书与采购模块，C 负责购物车与订单模块，每人分三次上传。
- 第一轮上传源代码和测试基础配置；三人的第一轮全部完成后，再进行第二、三轮测试代码上传。
- `package.json`、`pnpm-lock.yaml`、`tsconfig.json`、`cypress.config.ts` 后续上传到 `3测试代码及产品源代码/be/`，`server.ts` 上传到其 `src/` 目录。
- 保留现有路径，将文件放入对应目录，避免重复嵌套 `be/` 或 `3测试代码及产品源代码/`。
- `.gitkeep` 用于保留空目录；对应目录上传实际文件后，可以删除该目录中的 `.gitkeep`。
- 不上传 `node_modules/`、系统杂项文件和测试运行生成的视频、截图。
- 当前提交仅建立目录骨架，源代码、测试代码和运行配置由小组成员后续上传。
